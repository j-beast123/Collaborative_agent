# Checkpoint reproducibility package

This local artifact freezes the code, LoRA adapter, prompts, data identities and execution contracts used for the reported result. The saved result is physician final-decision accuracy `442/622 = 71.0609%` after collaboration.

The Agent is `Qwen/Qwen3-8B` loaded by Hugging Face Transformers at revision `b968826d9c46dd6066d109eabc6255188de91218`. The Agent is not served by Ollama. Ollama serves only the Gemma 3 12B Doctor.

## Frozen method

- Agent: Qwen3-8B with rank-16 RS-LoRA (`alpha=32`) on `q_proj`, `k_proj`, `v_proj`, and `o_proj`.
- Doctor: `gemma3:12b-it-q8_0`, digest `997a7c2c09753e9011ec18a3fcb498e27c0ba330599dfb26a2e05b58cfbdc1bc`, Ollama 0.12.5.
- Rollout: response-level tree GRPO, branching factor 4, maximum 4 Agent turns, adaptive stopping only after at least 2 Agent turns.
- Reward: rubric only (`w_outcome=0`, `w_rubric=1`); applicable KEEP rubric levels are normalized as 0, 0.5, and 1 and averaged.
- Advantage: mean-centered within same-state sibling responses.
- Optimizer: learning rate `1e-5`, KL beta `0.04`, clip epsilon `0.2`.
- Partner-side reflection: Claude Haiku 4.5 observer using `prompts/sherpa/behavior_feedback_v5.txt`. It retrospectively tracks the Doctor's request, response to the Agent, and unresolved need. It is a separate observer role rather than text generated by the local Gemma Doctor itself.
- Rubric generator: Gemini 3.8 Flash.
- Gate and scorer: GPT-5.6 Luna.
- Prompt reflection/refinement: Claude Sonnet 5.5.
- Verification: up to three intervention reruns; KEEP requires the target outcome in 2/3 trials under the recorded bounded-witness procedure.

The complete original configuration and runtime transitions are preserved under `artifacts/reported_checkpoint/provenance/`.

```bash
cd /path/to/Collaborative_agent_sherpa_final

# Install the CUDA 12.4 build of torch 2.6.0 using the appropriate PyTorch index,
# then install the remaining frozen Python packages.
python -m pip install -r requirements-eval.txt
```

Confirm that Git LFS downloaded the real adapter rather than its pointer:

```bash
sha256sum artifacts/reported_checkpoint/adapter/adapter_model.safetensors
# e81c3975dab9f9cc08965563aacd1b1cfce5dae90cdbb22e5a83849e3acae178
```

The base model is downloaded automatically from the pinned Hugging Face revision unless it is already cached.

## Doctor service

Install Ollama 0.12.5 and make the exact `gemma3:12b-it-q8_0` model available. The evaluator refuses to run if the server reports a different model identity. Start it on the expected endpoint, for example:

```bash
CUDA_VISIBLE_DEVICES=0 OLLAMA_HOST=127.0.0.1:11535 ollama serve
```

## Re-evaluate the packaged reported checkpoint adapter

The first command performs only local file/hash validation and does not load a GPU model:

```bash
python scripts/online_rl/eval_checkpoint.py
```

Run the resumable 622-case evaluation:

```bash
python scripts/online_rl/eval_checkpoint.py \
  --doctor-endpoint http://127.0.0.1:11535 \
  --device cuda:0 \
  --out outputs/checkpoint_eval \
  --launch
```

The adapter directory is read only. New results are written only under the supplied `--out` directory. Interrupted evaluation resumes from completed case files, and an output directory with a different identity is rejected.

## Re-run training through the reported checkpoint

The exact 500-case source order is packaged, while the reproduction configuration stops after its first 30 cases:

```bash
export SHERPA_FIVE_GPU_CONFIG=configs/online_rl/paper_reproduction.json
export SHERPA_OLLAMA_BINARY=/absolute/path/to/ollama-0.12.5/ollama
export SHERPA_OLLAMA_MODELS=/absolute/path/to/ollama/models
export SHERPA_ENV_FILE=/absolute/path/to/private.env

# Dry preflight: no GPU or API calls.
python scripts/online_rl/run_five_gpu.py --config "$SHERPA_FIVE_GPU_CONFIG"

# Five-GPU training and the reported-checkpoint evaluation.
bash scripts/online_rl/launch_five_gpu.sh
```

The private environment file must supply the API credentials needed by the frozen feedback, rubric, Gate/scorer and prompt-update roles. Never commit this file.

## Verification and limitations

```bash
pytest -q tests/test_checkpoint_handoff.py
pytest -q tests/test_checkpoint_handoff.py tests/test_gpu_pool.py
```

Artifact checks and GPU-pool tests are separate validation scopes. GPU-pool tests require a compatible environment, including permission to create local sockets. Passing artifact checks alone does not verify GPU inference, API availability, or an optimizer update. The repository retains historical tests; this document does not claim that the entire suite passes.

## Qualitative reflection example

[`docs/partner_reflection_example.md`](partner_reflection_example.md) preserves one representative partner-aware trajectory, its stored post-trajectory reflection, and the resulting rubric. It is an explanatory example and is not an additional evaluation sample.

The original run manifest did not record its Git commit. Commit `anonymous-source` is the closest preserved repository anchor and contains the matching portable five-GPU pipeline; artifact, prompt, model and protocol hashes are the authoritative identities. Fresh stochastic generation can differ across GPU types or inference-library kernels even with the same seeds. The committed per-case files preserve the observed result used for reporting.

The package verifies parsing and aggregation: all 622 FINAL outputs have one valid option, stored predictions match the FINAL text, and the recomputed count is 442 correct and 180 incorrect. This does not independently validate the medical correctness of the source dataset's answer key.
