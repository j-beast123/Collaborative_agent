이 서버에서 Agent v2/v3 평가를 준비하고 실제로 실행해줘. 아래 기준을 임의로 바꾸지 마.

목적
- 학습 전 Base Qwen3-8B와 원본 Full C30을 동일한 조건에서 비교한다.
- 실행 순서는 Base+v2 → Base+v3 → C30+v2 → C30+v3다. 각 arm별로 저장하고, C30 어댑터가 없으면 Base 두 조건을 먼저 끝낸다.
- v2는 기존 prompts/agent.txt의 바이트 동일 복사본 prompts/agent_v2.txt이며, 이번 전달을 위해 붙인 별칭이다. v3는 사용자가 제공한 새로운 원문이다.
- 같은 프롬프트에서 Base↔C30은 학습 효과, 같은 정책에서 v2↔v3는 프롬프트 효과로 구분한다. 대각선 비교를 순수 학습 효과라고 부르지 않는다.
- 기존 서버의 GPU5에서는 기존 agent.txt로 별도 Base/C30 비교가 진행 중이다. 이 서버의 v3 결과를 그것과 혼합하지 않는다.
- 학습 작업이 아니라 평가다. Doctor는 로컬 Ollama Gemma 3 12B Q8이다. OpenRouter/API Doctor 및 별도 private review를 사용하지 않는다.

먼저 읽을 파일
1. handoff/agent_v3/base_config.template.json (v3), base_config_v2.template.json (v2)
2. handoff/agent_v3/reproduction_manifest.json
3. prompts/agent_v3.txt
4. src/online_rl/runtime.py, src/online_rl/environment.py, src/online_rl/agent_protocol.py
5. src/online_rl/doctor.py, scripts/online_rl/prepare_casimedicos622.py

데이터와 가중치
- CasiMedicos 영어 전체 622문제, manifest에 기록된 순서 그대로 사용한다. 랜덤 재추출하지 않는다.
- 원문은 Git에 포함되지 않았다. 원래 서버의 data/interim/casimedicos/all_en_622.jsonl을 전달받거나 HiTZ/casimedicos-exp의 영어 train/dev/test를 내려받아 기존 prepare_casimedicos622.py로 정규화한다.
- 정규화 파일 SHA256과 전체 case_id 순서가 reproduction_manifest.json과 일치해야 한다. 불일치하면 임의로 무시하지 말고 원인을 보고한다.
- Base HF 모델: Qwen/Qwen3-8B, revision b968826d9c46dd6066d109eabc6255188de91218. 모델을 그 revision으로 받아 로컬 경로를 config에 설정한다.
- Base는 init_adapter=null + 제공된 고정 seed의 RS-LoRA 초기화다. lora_B가 모두 0임을 검증하고, 계산한 policy SHA가 manifest의 base_policy_sha256과 같은지 확인한다.
- C30은 일반 HF 모델 이름이 아니라 별도 학습된 어댑터다. 원래 서버 /home/kai/models/sherpa/c30/adapter 디렉터리를 별도로 받아야 한다. Git에 가중치는 없다.
- adapter_config.json과 adapter_model.safetensors를 받아 파일 SHA 및 로딩 후 policy SHA를 manifest와 대조한다. C30 가중치가 없으면 Base부터 진행하고 C30만 대기한다. 다른 체크포인트를 C30으로 대체하지 않는다.
- Ollama 0.12.5, gemma3:12b-it-q8_0 모델 digest는 config에 명시되어 있다. 다른 버전/양자화로 조용히 대체하지 않는다.

고정 실행 조건
- template의 rollout 설정, min 2/max 4턴, Agent temperature 0.7/top_p 0.9/top_k는 template의 null로 두고 pinned 모델 generation_config에서 20으로 해석되는지 검증, Doctor temperature 0.4를 유지한다.
- 먼저 실제 template의 값과 일치하는지 확인한다. episode seed는 case_index(0부터)로 고정한다.
- Agent precommit_v1 유지: 문제만 보고 독립 판단한 뒤 그 판단을 hidden block에 넣어 응답한다. enable_thinking=False 유지. v3의 silently 문구는 native reasoning ON이 아니다.
- 닥터/Agent 둘 다 원본 문제와 대화만 사용한다. 정답은 final_outcome 계산에만 사용하고 모델 입력에 넣지 않는다.
- 네 조건 모두 동일한 첫 Doctor 발화 D1을 공유한다. Base 실행 시 로컬 Doctor가 만든 D1의 visible/raw/status와 seed를 case별 저장하고 C30 실행 시 동일 opening을 재사용한다. 이 방식은 기존 71.06% 실험의 D1 원문까지 복원했다는 뜻은 아니다. 원본 D1 cache를 추가로 전달받지 않았다면 새 공유 D1임을 명시한다.
- Agent와 Doctor 프롬프트 및 종료 코드를 임의로 수정하지 않는다. 같은 프롬프트의 Base/C30 차이는 adapter와 출력 폴더뿐, 같은 정책의 v2/v3 차이는 Agent system 프롬프트와 출력 폴더뿐이어야 한다.

실행기
- 이 패키지는 프롬프트/설정/재현 지시문이며 새 평가 실행기는 아직 포함하지 않았다. 저장소의 SharedPolicy.generate(case, seed, opening=...)와 기존 평가 구현을 재사용해 다른 서버 경로에 의존하지 않는 실행기를 작성하라.
- SharedPolicy가 선택한 GPU에서 로드되도록 torch import 전 CUDA_VISIBLE_DEVICES를 설정한다. 현재 서버의 GPU 번호 5를 그대로 강제하지 않는다. 사용 가능한 GPU를 조사하고 다른 사용자의 작업을 종료하지 않는다.
- 모델 1벌로 시작하고 Agent batch=1, 동시 episode=1로 네 조건 모두 동일하게 설정한다. PyTorch/Transformers/PEFT 및 CUDA 버전을 기록한다.
- model.eval(), use_cache=True 및 gradient_checkpointing_disable()를 적용한다. per_row_rng_batch_v1를 유지한다.
- API key가 없어도 실행 가능해야 한다. DoctorUnavailable, timeout, 빈 FINAL은 오답으로 조용히 처리하지 말고 기술적 오류로 기록한다. 재시도는 같은 seed/입력으로 제한된 횟수만 수행한다.
- 먼저 별도 smoke 출력에 2문제를 평가하고, 모델 hash/Doctor digest/전체 dialogue 저장과 파싱을 확인한다. 통과하면 본평가 622문제를 Base+v2 → Base+v3 → C30+v2 → C30+v3 순으로 백그라운드 실행한다. 실패 원인이 해결되지 않으면 전체 평가를 시작하지 않는다.
- resume은 config/prompt/model/dataset hash와 완료 case_id를 확인한 후 누락 문제만 실행한다. 다른 설정의 기존 결과를 합치지 않는다.

출력
outputs/agent_prompt_compare/<run_id>/{v2,v3}/{base,c30} 아래 각각:
- manifest.json: prompt 원문/해시, config, model/adapter/Doctor digest, code commit, 패키지 버전, data SHA, seed, 실행 GPU
- cases/case_XXXXXX.json: case_id/index, 전체 공개 대화, Agent private assessment/visible response 및 입력 trace, Doctor status/final decision, outcome, elapsed time
- summary.json: 완료/전체/정답/오답/파싱실패/기술오류, 정답률, 평균 턴, 최근 속도/예상 종료
- runner.log와 PID, 공유 D1 cache
- 최종 comparison.csv: 동일 case_id별 네 조건 정답 여부, 최종 선택, 턴수, 정답→오답/오답→정답 전환. v2/v3별 학습 효과와 Base/C30별 프롬프트 효과를 별도 집계
- 추후 닥터 수용률 분석이 가능하도록 모든 Agent 발화와 그 직전/직후 Doctor 발화를 보존한다. 이번 요청에서는 외부 LLM 채점을 자동으로 추가하지 않는다.
