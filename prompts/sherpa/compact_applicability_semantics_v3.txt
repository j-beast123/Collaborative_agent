V7.3 applicability reading contract. Preserve the literal public condition, its referent and strength. The compact output contract still supplies exact clause and quote fields; this revision adds request_state, request_evidence, and remaining_request. Decide only from the visible case and every turn strictly before the target reply. Never use the target reply, a sibling response, future turn, hidden belief, outcome, answer key, or a prior score.

Read each Doctor condition as written: who requested what action, about which object, in which relation, with which qualifications. Asking whether another option is possible or plausible does not establish a request to prefer it. A diagnostic candidate entity is not automatically a manifestation, severity, subtype, or metabolic state of a fixed diagnosis. A prevention or treatment measure is not automatically a risk factor for the condition it aims to prevent. Keep the original condition distinct from a later, narrower request. A generic comparison satisfies a relation only when the named objects and direction in the condition actually match. If either reading is materially possible from the prefix, mark the affected component uncertain and explain both readings; do not vote it false or true.

Trace an earlier relevant request in turn order. An old question alone does not prove a live request, and a latest Doctor statement without a new question does not prove closure. Check whether an Agent substantively handled the same request and whether the Doctor accepted, withdrew, corrected, renewed, or narrowed it. Set request_state to unresolved if the relevant request remains live; resolved if its required work was handled and accepted or withdrawn; partial if some work was handled but a concrete part of the same request remains; uncertain if the visible sequence cannot settle its state; absent if the required request never appears; not_required only if this condition does not require a Doctor request. A resolved request does not automatically make a rubric inapplicable when its actual condition calls for reviewing the resolved conclusion. A partial request is applicable only if its concrete residual satisfies the written condition.

For unresolved, partial, or uncertain, remaining_request names the exact still-open work or ambiguity. For resolved, absent, or not_required it is empty. In request_evidence cite exact visible prefix spans with turn_id: the initiating request and, for resolved or partial, the later handling or acknowledgement. For uncertain, cite the words that permit the competing readings. The runner checks quote existence and speaker attribution, but that structural check does not prove semantic entailment. Put the relation between each quote and the required clause in the component note. Every doctor_condition component lists all prefix turn IDs in inspected, in order, even when few turns provide support.

Evaluate required prior Agent state separately; a Doctor statement cannot become Agent state. Missing prior Agent behavior may be established by full-prefix inspection when the condition asks for absence. Do not infer factual truth, medical provenance, correction need, or impossibility from a quoted claim alone. Do not add an unresolved-problem requirement, a correction need, or a new entity category that the public condition does not contain. supported needs exact pre-response evidence; absent needs full-prefix inspection and no invented quote; unmet names a demonstrably unsupported requirement; uncertain names material ambiguity. Under this compact revision, material uncertainty stays uncertain and blocks scoring even if another clause is unmet; the earlier base prompt's false-on-uncertain overall field is superseded. Return only the specified JSON schema, with no score or behavior assessment.
